# Design notes: AQUA self-pruning network

## 1. Importance criterion

For one scalar weight `w`, removing it means changing it to zero, so `delta_w = -w`. A first-order Taylor expansion gives

`L(w + delta_w) ~= L(w) + (dL/dw) * delta_w`

and therefore the signed predicted change is `delta_L ~= -w * dL/dw`. The score used here is `abs(w * dL/dw)`, the magnitude of the first-order estimate. This incorporates both parameter size and local loss sensitivity, unlike magnitude-only pruning. It is only a local approximation: interactions between weights and second-order curvature can make actual loss changes differ. Scores are averaged over minibatches and used to rank currently active weights. Magnitude pruning is retained as the baseline.

## 2. Gradient of a masked weight

The effective weight is `W_eff = W * M`, where `M` is a fixed binary mask. By the chain rule, `dL/dW = M * dL/dW_eff`. Thus the gradient with respect to the underlying parameter is exactly zero where `M=0`. The hypothetical derivative with respect to `W_eff` can be nonzero; that separate signal can support regrowth, but this implementation does not enable regrowth by default.

A zero gradient alone is insufficient with Adam: the first moment may remain nonzero and continue moving a parameter. On pruning, this implementation zeros the underlying parameter and clears its first and second moments. During every optimizer step, masked gradients, parameters, and moments are masked again. If a connection were revived, the safest simple policy is to initialize it explicitly and reset its optimizer moments rather than reusing stale state. A future regrowth feature should define the hypothetical importance signal, initialization, and optimizer-age policy.

## 3. Engine bottlenecks

This engine is intentionally educational. Python graph nodes and closures create overhead; each primitive operation allocates NumPy arrays; backward traverses nodes in Python; and the sparse inference implementation loops over active edges. Improvements include graph-node reuse, fewer intermediate copies, fused loss/activation operations, vectorized sparse kernels or CSR/CSC storage, and compiled kernels. Benchmark before optimizing.

## 4. Multi-tenant inference design

Training/pruning should happen offline. Validate accuracy, sparsity, artifact integrity, and latency, then publish immutable, versioned model artifacts (weights, masks, architecture, metadata). Serving workers load a pinned model version; requests never mutate shared parameters. Isolate tenant quotas, authentication, request budgets, and telemetry. Batch compatible requests where latency SLOs permit. Measure p50/p95/p99 latency, throughput, memory, error rate, and quality drift per model version. Use staged rollout and a fast rollback to a known-good artifact. Benchmark on target hardware: unstructured sparsity only improves latency when the runtime/kernel can exploit it; active parameter counts alone do not prove speedup.

## 5. Evidence protocol

Use identical architecture, data-generation procedure, training budget, and seeds for the pruning-method comparison. Report achieved—not merely requested—sparsity, test accuracy, and variation across seeds. Mean and standard deviation summarize run variability but are not by themselves a significance test. The included sweep is designed to produce raw CSV and a plot; numbers must be generated by running the code and must not be fabricated or copied from illustrative examples.
